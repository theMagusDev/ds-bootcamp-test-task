# Avito: отбор кандидатов

Решение возвращает до 50 объявлений для каждого поискового запроса. Лучший результат в тестирующей системе: **Recall@50 = 0.799730**.

## Быстрый запуск

Данные не входят в репозиторий. Для запуска нужны три файла из архива, предоставленного организаторами:

- `train.parquet`;
- `benchmark_queries.parquet`;
- `benchmark_items.parquet`.

Итоговую посылку полностью строит `01_final_solution.ipynb`. Остальные ноутбуки для её воспроизведения не требуются.

### Вариант 1: запуск на Kaggle

1. Создать Kaggle Notebook и импортировать в него `01_final_solution.ipynb`.
2. Через **Add Input** подключить датасет, содержащий три файла, перечисленных
   выше. Файлы должны лежать непосредственно в одной папке, как в исходном
   архиве организаторов.
3. В настройках ноутбука включить **Internet** и выбрать **GPU Accelerator**.
4. Проверить путь `KAGGLE_DATA_DIR` в первой конфигурационной ячейке. Если
   Kaggle подключил датасет по другому пути, заменить значение на фактическую
   папку, например:

   ```python
   KAGGLE_DATA_DIR = Path("/kaggle/input/<dataset-name>")
   ```

5. Выполнить **Restart & Run All**.
6. После успешного выполнения скачать `/kaggle/working/answer.csv`.

Если датасет доступен по пути `/kaggle/input/datasets/yuriymagus/avito-nlp-interns`, менять конфигурацию не нужно.

### Вариант 2: локальный запуск

Распаковать исходный архив в папку `data` в корне репозитория. Ожидаемая
структура:

```text
avito-solution/
├── README.md
├── requirements.txt
├── 01_final_solution.ipynb
├── 02_eda_and_validation.ipynb
├── 03_lexical_baselines.ipynb
├── 04_hybrid_experiments.ipynb
└── data/
    ├── train.parquet
    ├── benchmark_queries.parquet
    └── benchmark_items.parquet
```

Для локального запуска рекомендуется Python 3.12 и отдельное виртуальное окружение. Создать его из корня репозитория:

Linux и macOS:

```bash
python -m venv .venv
source .venv/bin/activate
```

Windows (cmd):

```cmd
python -m venv .venv
.venv\Scripts\activate
```

Установить зависимости и запустить Jupyter Lab:

```bash
python -m pip install -r requirements.txt
python -m pip install pandas pyarrow jupyterlab
jupyter lab
```

Открыть `01_final_solution.ipynb` и выполнить **Restart Kernel and Run All**. Ноутбук следует запускать в ядре Python из активированного окружения `.venv`. При такой структуре менять пути не требуется. Итоговый файл будет сохранён как `answer.csv` в корне репозитория. После завершения работы окружение можно деактивировать командой `deactivate`.

Если данные или результаты должны находиться в других папках, можно изменить пути в первой конфигурационной ячейке либо задать абсолютные пути через переменные окружения.

Linux и macOS:

```bash
export AVITO_PROJECT_DIR=/absolute/path/to/avito-solution
export AVITO_DATA_DIR=/absolute/path/to/data
export AVITO_OUTPUT_DIR=/absolute/path/to/output
jupyter lab
```

Windows PowerShell:

```powershell
$env:AVITO_PROJECT_DIR = "C:\path\to\avito-solution"
$env:AVITO_DATA_DIR = "C:\path\to\data"
$env:AVITO_OUTPUT_DIR = "C:\path\to\output"
jupyter lab
```

`AVITO_DATA_DIR` должен указывать именно на папку с тремя файлами Parquet, а не на родительскую папку или ZIP-архив.

## Проверка результата

Перед сохранением ноутбук автоматически проверяет, что:

- присутствует строка для каждого `query_id`;
- в ответе нет неизвестных или повторяющихся `item_id`;
- для одного запроса возвращается не более 50 объявлений;
- сохранены ровно две колонки: `query_id` и `answer`.

В конце выполнения печатаются путь к `answer.csv` и его SHA-256. Хеш также можно проверить отдельно.

Linux и macOS:

```bash
sha256sum answer.csv
```

Windows PowerShell:

```powershell
Get-FileHash .\answer.csv -Algorithm SHA256
```

Если известен контрольный хеш отправленного файла, его можно передать через `AVITO_EXPECTED_SHA256`: ноутбук завершится с ошибкой при несовпадении.

## Файлы репозитория

- `01_final_solution.ipynb` — самостоятельное воспроизведение итоговой
  посылки;
- `02_eda_and_validation.ipynb` — анализ данных и схема офлайн-валидации;
- `03_lexical_baselines.ipynb` — TF-IDF, BM25, BM25F и учёт локации;
- `04_hybrid_experiments.ipynb` — история, микрокатегория, E5 и перенос
  локации.

Для получения посылки достаточно запустить `01_final_solution.ipynb` целиком.
Остальные ноутбуки нужны для обоснования выбранной конфигурации.

## Настройка путей

В начале каждого ноутбука определены:

```python
PROJECT_DIR
DATA_DIR
OUTPUT_DIR
```

На Kaggle рабочая папка и папка результатов определяются автоматически. При локальном запуске без переменных окружения `PROJECT_DIR` равен текущей рабочей папке, данные читаются из `PROJECT_DIR / "data"`, а результаты сохраняются в `PROJECT_DIR`.

## Итоговая схема

1. BM25F по лемматизированным заголовкам и описаниям с весами `1` и `1/3`.
2. Приоритет объявлений из той же локации.
3. До 10 объявлений из истории одинаковых запросов.
4. До 20 объявлений из предсказанной микрокатегории.
5. До 20 кандидатов векторного поиска `intfloat/multilingual-e5-small`.
6. До 10 объявлений из локации, восстановленной по истории, если точной
   локации запроса нет в корпусе.

Порядок строк корпуса не влияет на BM25F-выдачу: одинаковые оценки разрешаются по `item_id`. Финальные параметры зафиксированы и не выбираются заново при запуске итогового ноутбука.

## Валидация

Обучающая выборка разбивается по нормализованной формулировке запроса. Одна формулировка не может одновременно попасть в обучение и валидацию. Поскольку для события train известно одно выбранное объявление, офлайн используется `HitRate@50`. В закрытом benchmark релевантных объявлений может быть несколько, поэтому итоговая метрика — `Recall@50`.

## Ошибки и особенности данных

- одинаковые тексты запросов считаются разными поисковыми событиями, а не
  ошибочными дублями;
- обнаруживаются отрицательные цены и значения вне допустимых диапазонов;
- цена и координаты не используются в итоговой модели;
- рейтинг и число отзывов используются только как последний резерв для выдач
  без достаточного числа текстовых совпадений;
- строки с ошибочными значениями не удаляются, чтобы не терять взаимодействия;
- пропущенные текстовые поля заменяются пустой строкой;
- валидационный корпус содержит только `item_*`-поля и сортируется по `item_id`,
  поэтому положение таргета не влияет на ранжирование.

## Окружение

Итоговый прогон выполнялся на Kaggle с GPU и включённым интернетом. В ноутбуке зафиксированы версии `pymorphy3`, `sentence-transformers`, `transformers` и `faiss-cpu`; PyTorch и CUDA берутся из образа Kaggle. Модель E5 загружается с Hugging Face и затем используется локально, без обращения к внешнему API.

`01_final_solution.ipynb` сохраняет `/kaggle/working/answer.csv` на Kaggle или `OUTPUT_DIR / "answer.csv"` локально и печатает SHA-256.
